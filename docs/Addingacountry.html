Adding a country

Holiday names come from a country package: one object per country, based on the cNationalHolidays class. The library has packages for the US, GB, NL, NO, ES and SE.

A package is a list of the country's holidays and special days. The days are looked up in the order they are listed, and the first one that falls on a date names it - so when two can fall on the same date, list the one that should win first (Christmas Eve before the 4th Advent Sunday, for example).

To add a country to your program:

  1. Copy a country package that is close to yours, such as NorwegianHolidays.pkg from the library, into your own workspace's AppSrc folder, and give the copy your country's name.
  2. Set psISO_Short to your country's two-letter code, and psLocaleName to the Windows name of its language, such as "de-DE": the month and day names in that language come from it.
  3. Change the list of days. AddDay adds a day that one of the library's date functions gives; AddFixedDay a day on the same month and day every year. The last argument is True for an official holiday - a day off by law - and False for a special day that is not.
  4. Use your package in your program, after the library: Use GermanHolidays.pkg after Use oCalendarHolidays.pkg. The object registers itself with the library as it is created.

Use cNationalHolidays.pkg


Object oGermanHolidays is a cNationalHolidays

    Set psISO_Short to "DE"

    Set psLocaleName to "de-DE"


    Send AddDay "NewYearsDay" "Neujahr" True

    Send AddDay "GoodFriday" "Karfreitag" True

    Send AddDay "EasterMonday" "Ostermontag" True

    Send AddFixedDay 10 3 "Tag der Deutschen Einheit" True

    Send AddDay "ChristmasEve" "Heiligabend" False

    Send AddDay "ChristmasDay" "1. Weihnachtstag" True

End_Object

That is all: every function of the library knows the country from then on - HolidayName, HolidayDetails, IsDateAHoliday and the working-day functions - and so does the demo: Year Overview gets a button for it, and Working Days and Dates Functions Test list it.

Days that need more

Right after a day is added, these change it:

  • SetDayYears iFromYear iToYear - the day applies only in those years (0: no limit). A day that became an official holiday in 2005 is two lines: official from 2005, not official up to 2004.
  • SetDayOffset iDays iWeekday - the day is some days before (-) or after (+) the function's or fixed date, such as Shrove Tuesday, the day before Ash Wednesday. When iWeekday is not 0, only when that date is that ISO weekday (6 Saturday, 7 Sunday) - for a holiday observed on the Friday before when it falls on a Saturday.
  • SetDayAlsoOn sFunction - the day counts only when the date is also that function's date: the UK's "Christmas Day (UK)" is Christmas Day when the Christmas Day bank holiday falls on it.

See SwedishHolidays.pkg, AmericanHolidays.pkg and BrittishHolidays.pkg in the library for each of them in use. A misspelt function name is reported when the program starts.

The library's own country packages are Used in CountryPackages.pkg. Do not add yours there: in DataFlex 26 the library is an installed package, which is read-only. Edit CountryPackages.pkg only when you add the country to the library itself - see Share it below.

Working days

The working-day functions ask the country package which days are official days off: by default, the days listed as official. When a country's days off differ by region, as in the UK, the package can give region bits instead of True or False (Set pbRegionBits to True) and override the IsOfficialDayOff function; see BrittishHolidays.pkg for an example.
